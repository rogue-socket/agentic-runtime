# agentic-runtime — Gap Analysis

**Date:** 2026-03-17

---

## Context

The runtime has a solid execution engine: runs, steps, retries, branching, resume, replay, persistence, visualization, agent manifest packaging, LLM provider registry, built-in LLM handler, and a full CLI. All of that is implemented and tested where noted.

This document identifies what is **missing or incomplete** — the gaps between the current codebase and a product that developers can use to run real AI agents.

Gaps are ranked by severity: how much they block real-world adoption.

**Updated 2026-03-18** — gaps 3, 5, and 6 have been resolved. Gap 2 partially addressed with lifecycle hooks.

---

## Gap 1: LLM quickstart is not the default (High)

**Impact:** Users still experience stub-like workflows by default.

LLM calls and the built-in `handler: llm` exist, but `ai init` and sample workflows still showcase stub handlers. A new user can configure providers and still not see a real LLM call without editing YAML and code.

**What's needed:**
- Update `ai init` to scaffold a working LLM workflow
- Add a sample that uses `handler: llm` with a real prompt
- Add a “quickstart” path that runs an LLM step and opens a visualization

**Files involved:** `cli.py`, `llm/handler.py`, `workflows/samples/`

---

## Gap 2: No streaming or progress feedback (High)

**Impact:** Poor UX for long-running LLM or tool steps.

**Status: Partially resolved (2026-03-17/18).** Lifecycle hooks (`EventCallback`) now emit events at RUN_START, STEP_START, STEP_COMPLETE, STEP_ERROR, RUN_COMPLETE. CLI shows real-time step progress. Per-step timing telemetry (handler_duration_ms, tool_duration_ms) added. **Remaining:** streaming token output from LLM calls — requires adapter-level chunked response parsing.

---

## Gap 3: Memory tiers are incomplete and unsafe to hydrate (High)

**Status: RESOLVED (2026-03-17).** 

- MemoryManager now uses namespaced deep-merge under `runtime.memory.<tier>` — state corruption eliminated.
- WorkingMemory fully implemented: scratch store (byte budget), sliding window entries, active task tracking.
- SemanticMemory fully implemented: SQLite + FTS5, CRUD, full-text search, tag retrieval.
- ProceduralMemory remains a stub with documented roadmap.

---

## Gap 4: Sync API cannot run inside existing event loops (Medium)

**Impact:** Embedding the runtime in async apps is awkward.

The sync entrypoints call `asyncio.run()`, which fails if a loop is already running (FastAPI, Jupyter). Users must remember to call the async API.

**What's needed:**
- A safe sync wrapper that works inside running loops
- Or an explicit async-first SDK surface with clear guidance

**Files involved:** `core.py`

---

## Gap 5: CLI input type handling (Medium)

**Status: RESOLVED (2026-03-17).** `_coerce_value()` auto-parses `-i key=value` args: bool → int → float → JSON → str fallback. Workflow input declarations support `description`, `required`, `default` for type documentation.

---

## Gap 6: Security hardening follow-ups (Medium)

**Status: RESOLVED (2026-03-17).**

- `FileTool._safe_path` prefix bypass fixed — uses `os.sep` suffix check.
- `import_agent` rejects symlinks/hardlinks in tar archives.
- Manifest paths validated against project root via `_safe_copy`.
- `ShellTool` allowlist/denylist with regex-based command filtering.
- `safe_eval` blocks dunder attribute access.

---

## Gap 7: Minimal expression language for branching (Low-medium)

**Impact:** Forces workarounds for non-trivial conditions.

Branch conditions use `safe_eval` restricted to `state` and `len`. This limits string operations, membership tests, and complex predicates.

**What's needed:**
- Expand allowed expressions or add a safe helper library
- Preserve determinism and avoid unsafe execution

---

## Gap 8: No multi-agent or sub-workflow composition (Low)

**Impact:** Limits orchestrator patterns to single workflows.

Each agent runs one workflow. No mechanism for:
- One agent calling another agent
- A step invoking a sub-workflow
- Workflow composition

---

## Gap 9: No authentication or authorization (Low)

**Impact:** Blocks shared/production use.

No access control exists. Anyone with CLI access can run agents, read runs, and resume runs.
